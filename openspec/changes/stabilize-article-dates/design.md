# Design

## Context

动机见 `proposal.md`，行为契约见 `specs/article-timestamps/spec.md`。本设计延续 `docs/designs/2026-11-03-article-dates.md` 的访谈结论；OpenSpec 提案是本次审阅入口，旧访谈文档保留为背景，不重复维护另一份实施任务。

本地工作区声明 Hexo 8.1.2、Fluid 1.9.9 和 pnpm；当前本地 HEAD 的 package.json 仍声明 Hexo ^7.1.1、Fluid ^1.9.7，未设置 packageManager。本地依赖变更尚未提交，线上版本需按实际部署提交与日志核对。`package.json` 的构建命令是 `hexo generate`；根配置的 `updated_option` 为 `mtime`、时区为空，首页按 `-date` 排序。已安装的 Hexo 处理器在缺少日期时使用文件 birthtime/mtime。`update.py` 又会将 mtime 写入 `date`，因此不能仅调整 Git 换行配置。

当前没有站点自有 `scripts/` 日期扩展或相关自动化测试。Hexo 在运行生成器前执行 `before_generate`，可用于统一设置文章模型时间；Fluid 已提供原生更新时间提示，当前配置关闭。用户本轮确认沿用原生显示规则，不再要求时间相同时也显示两个字段，因此无需自定义展示模板。

当前 HEAD 为 4193cf0。81 篇缺失发布时间通过 3167153 上线，49 篇缺失或空 title 通过 4193cf0 上线，用户均已确认。当前 124 篇文章都有 date 和非空 title；本轮不重做已完成的日期或标题写入。

本地有完整可达历史，但不保证包含真实首发；有文章重命名。Vercel 最近生产部署日志已证明使用 pnpm install --no-frozen-lockfile，并执行仓库的 clean/build；实际 Git 克隆深度尚未打印。工作区已有用户的依赖、文档及文章修改，实施不得清理或覆盖它们。

## Goals / Non-Goals

**Goals:**

- 让迁移命令、旧更新入口与构建共用同一日期推导核心，避免三套规则分叉。
- 将源文件中的固定发布时间与构建模型中的动态更新时间分开；构建不得产生源 Markdown 的更新时间提交。
- 在有限且明确的附件归属边界内追踪历史，包括文件删除、重命名、共享附件及缓存复用。
- 使用仓库内扩展和 Git CLI，兼容 Windows、Linux，不维护时间数据库或主题依赖补丁。

**Non-Goals:**

- 不恢复没有版本记录的真实编辑或首发时刻，不用自动算法纠正已有 `date`。
- 不建立源码 import、XML、运行时文件或远程项目的递归依赖图，不自动归属全部同级文件。
- 不清理已跟踪的 `.class`、`.jar`、IDE 文件或脏子模块，不将本次工作扩大为附件结构整改。
- 不自动发布到 Vercel、修改 Vercel 账户设置、提交或推送用户现有工作区。

## Decisions

### 1. 采用共享的仓库内 Node.js 日期核心

计划在 `lib/article-timestamps/` 放置可被独立测试的历史与依赖解析逻辑，在 `scripts/` 放置 Hexo 自动加载的薄适配层，在 `tools/` 放置迁移与历史准备命令。工具文件不放进 Hexo 自动加载目录，避免构建时执行 CLI 主流程。

以 Git 提交者时间 `%cI` 表达入库和有效变更时刻。使用参数数组调用 Git，不经 shell 拼接；使用支持中文、空格及特殊字符的路径处理和 NUL 分隔输出。相同提交和声明必须产生相同结果。

替代方案：继续 mtime 无法跨检出复现；用 push 或上线时间不能定位具体文章；本地 hook 回写 `updated` 容易漏装、漏跑，并产生额外修改。共享构建核心可以统一这些行为。

### 2. `date` 保留并可一次性补齐，`updated` 每次生成派生

迁移默认只预览文章路径、现有值、候选值、来源提交和问题；显式写入范围限定为 source/_posts/ 下根仓库跟踪的 Markdown，只补缺失 `date`，保留正文、已有 front matter、编码及换行格式。没有 front matter 时只添加必要日期头，不顺带生成标题、标签或改写全文。Git 忽略的工程 HELP.md、子模块 README.md 及其他目录不写入，不改变其渲染行为。再次运行不产生变更。先完成预检，避免历史缺失时留下部分日期迁移。

构建使用同一首次入库算法为尚未持久化日期的文章提供 Git 派生值，不允许 Hexo 的 birthtime 回退流入页面。已有有效 `date` 保留其原有含义，不受新提交影响；日期解析需显式按配置时区处理。无法解析的日期报告为错误；已有 `date` 晚于派生 `updated` 时报告矛盾，不擅自重写或钳制其中一个值。

`before_generate` 对实际文章集合逐篇设置模型中的 `date` 和 `updated`，覆盖静态 `updated`，每次生成都核对附件。配置改为 `updated_option: date` 作为禁止 mtime 的基础设置，但插件历史计算失败必须中止，不能依赖该回退伪装成功。

替代方案：每次构建回写两种时间会制造额外提交，并让迁移反过来改变更新时间；全部用首次提交覆盖现有 `date` 则违背保留现有日期的选择。

### 3. 有效变更比较排除换行及时间字段维护

对文本内容仅统一 CRLF/LF；保留正文其他空白，不能使用整体忽略空白的 Git 比较选项。文章通过 front matter 结构识别顶层 `date`、`updated` 字段，将这些字段从有效内容比较中排除；只含时间字段的空日期头与无头正文等价。保留其他元数据的值、结构以及正文排版变化，不能用简单的未锚定正则删除正文中的同名文本。二进制附件按原始内容比较，不做换行转换。

用户已单独确认仅维护时间字段不算内容更新；该规则避免首次补日期使所有文章同时更新。替代方案是将迁移提交特殊列入忽略清单，但这会引入长期维护的提交例外。用户已确认实现仓库内扩展方案，本轮执行本地实现与验证，不自动提交或推送。

补充确认：仅补齐缺失或空 title 不算文章更新，修改已有非空 title 仍算更新。这是按变更前后字段状态判断的一般规则，不使用特定提交忽略清单，也不能通过全局忽略 title 字段实现。新文章首次入库仍为有效内容提交；同一提交中若还有正文、标签或关联附件的变化，仍按其他有效变化更新时间。

2026-11-03 的旧文复查原有 43 个 date、81 个缺失；用户选择保留现值、缺失按首次入库时间补齐，已通过 3167153 完成并上线。9 个额外工程说明不写日期、不改渲染。事实与样本见 `docs/research/2026-11-03-existing-article-dates.md`，当时确认的候选见 `docs/research/2026-11-03-article-date-fill-preview.md`；该预览保留为迁移前记录，不是当前缺失日期清单。

### 4. 正文引用自动解析，配套工程显式声明

使用语法解析取得 Markdown 图片、文件链接和 HTML 中真实资源引用，跳过代码块、内联代码、外部协议和纯锚点。解析时沿用当前文章目录、站点根路径和 Hexo 资源目录规则，处理 URL 编码、片段及查询参数，限制最终依赖在仓库边界内，不能通过 basename 猜测失效路径。

新增可选 front matter 字段 `updated_assets`，值为相对文章 Markdown 所在目录的文件或目录路径数组。例如 `mybatis.md` 可以声明 `updated_assets: [code/mybatis/]`。目录由尾部斜线明确标识，即使目录中的文件后来全部删除，仍能查询其历史。声明字段本身属于非时间元数据，修改它会构成文章更新。

引用和声明合并去重。指定目录包括其中全部受版本控制文件，不按 `.class`、`.jar` 等扩展名静默排除；未归属文件不计入。子模块只追踪本仓库 gitlink 版本更新，不读取子模块工作区。

现有代码工程大多没有正文链接，因此先输出候选归属清单；仅写入能够由现有文章内容和目录用途明确确认的关系，歧义项列出待确认，不为所有文章猜测同级归属。自动检测到的旧失效图片引用按文章和路径报告，不能顺便批量修链接或把外链误归为本地附件。

替代方案：只按链接会漏掉用户要求的未链接配套工程；整目录自动归属会混入其他文章和无关文件；外部映射可以表达关系，但文章移动后需要维护两个位置，当前规模优先使用文章元数据。

### 5. 沿内容历史追踪重命名和删除，不只查询当前文件

首次入库时间追溯文章的文件历史；更新时间从 HEAD 对应文章内容、引用和显式归属建立依赖集合，再读取各依赖的有效变更。重命名由 Git 识别结果结合内容比较追溯，不能用文件名匹配推断身份，也不能只依赖相似度阈值认定纯重命名。Git 识别不到且无法确认身份时报告限制，不静默当作真实首发。

显式目录查询历史中的增加、修改、删除及路径迁移事件，不只对 `ls-files` 当前结果逐项执行 `log -1`。已删除的被引用文件仍参与其删除提交计算，并额外报告链接失效。共享资源的历史结果在一次生成中复用；相关资源的有效变更候选取最近提交者时间。

合并提交按实际内容变化判断，不因合并本身刷新日期；已存在的分支内容沿其来源追溯，合并冲突解决引入的新内容视为有效变更。批量读取历史元数据，按提交、路径和 blob 缓存比较结果，避免每篇文章重新扫描整个仓库。缓存不能仅以 Markdown mtime 为键，也不能持久化为跨版本日期事实。

本地已跟踪文章和附件的未提交修改用于正常内容预览，但日期及依赖历史计算使用已提交版本，不把本地保存时间混入。新文章尚无 Git 历史时给出明确提示，不伪造时间；需要查看正式日期时先提交到本地即可，不要求先 push。

### 6. 历史预检与 Vercel 构建入口

添加历史准备命令并接入仓库已有 `build` 路径，使生产构建在生成前检查 Git 元数据和克隆深度。完整历史直接使用；浅克隆时尝试仅补齐当前构建所需历史，不切换分支、不拉取工作区内容、不重写 HEAD。缺少远程权限或缺少 `.git` 时明确失败并给出修复方向；不回退到 mtime、当前时间或来源不明的静态 manifest。

本地迁移和预览同样预检历史，但离线时历史充分即可工作。Vercel 最新生产部署日志已确认执行 package.json 的 clean 和 build，分别运行 hexo clean 和 hexo generate。因此在现有 build 中加入历史准备即可进入当前部署流程；不需要为使本地脚本生效而更换平台或先手动修改控制台。

2026-11-03 的官方资料核查确认：Vercel 默认浅克隆最近 10 层提交；Install Command 与 Build Command 独立；仓库 `vercel.json` 的 `buildCommand` 可覆盖控制台构建命令。提案据此补充采用版本控制内的显式构建入口，调用统一的 package.json build；不依赖 Hexo 预设是否隐式优先执行 scripts.build。npm 可作为脚本执行器调用这一入口，不代表必须改变现有依赖安装工具。依据和账户访问边界见 `docs/research/2026-11-03-vercel-github-build.md`。

Vercel 插件及团队授权现已生效，已核实 endlessshws-projects/blog：框架为 hexo，Node 设置为 24.x，Git 集成使用 EndlessShw/blog 的 main，最新日期补齐部署 3167153 已 READY。构建日志检测旧 pnpm 锁文件格式 5.4，安装后调用 clean/build；未打印当前部署的实际 Node 或精确 pnpm 版本。版本控制内的 vercel.json 是防止配置漂移的提案选择，不是当前 build 被执行的先决条件。当前新功能尚未发布；提交或推送需用户另行指示，之前的日期推送授权不延伸为后续自动发布。

替代方案：隐藏历史不足并继续生成会违反跨环境一致性；在构建后用时间修补脚本改文件 mtime 仍将业务时间耦合到文件系统。

### 7. 沿用 Fluid 原生更新时间显示

设置 `timezone: Asia/Shanghai`，保留 `index_generator.order_by: -date` 和归档发布时间顺序。开启 `_config.fluid.yml` 的 `post.updated.enable`，使用绝对日期时间格式，由原生模板显示 Git 派生的 page.updated，不修改 `node_modules` 或新增 EJS 注入。

用户已确认：两个时间不同时显示文章开头更新时间提示；相同时只保留发布时间。版权区更新时间默认保持关闭，避免重复提示；首页发布时间及其他元信息不变。使用站点时区输出绝对时间，不将“动态更新时间”理解为每次刷新或重新部署都变成当前时刻。

替代方案：自定义片段可在时间相同时强行显示两个字段，但用户接受原生行为后已无必要；复制整个 post.ejs 或覆盖比较函数都会增加主题升级成本。

### 8. 一次性补齐缺失标题

完整清单见 `docs/research/2026-11-03-article-title-fill-preview.md`。仅处理根仓库跟踪的 49 篇缺失或空 title：42 篇取首个实际正文标题的展示文本，4 篇用用户单独确认的名称，3 篇写精确的“标题 TODO”；保留另外 75 个非空 title。

Markdown 使用语法解析，不用首个井号正则，不从代码块、空引用标题或普通段落提取名称。填入 YAML 时作为字符串正确引用；仅插入缺失字段或替换原空值，不重新序列化全文，保留 date、正文、换行与编码。不修改文件名或 slug；当前 Hexo 的 permalink :title/ 对应 slug，YAML title 对应另一占位符 post_title，因此补显示标题不会仅因同名占位而重建 URL。

标题补齐是一次性源数据整理，不在每次构建中追随正文标题覆盖已经存在的 title。执行前核对清单、每个目标的当前 title 状态和原文件字节，执行后通过逆向删除新增字段/恢复原空字段核对其他字节完全一致。动态更新时间比较单独识别“前值缺失或空、后值非空”的补齐，不全局忽略标题，也不忽略同提交中的正文或附件变化。

### 9. 旧入口转向统一规则

保留 `update.py`、`update.bat` 的已有调用形式，作为统一日期工具的薄入口或弃用提示；移除 mtime 写入 `date` 的路径。优先让 Python 包装使用参数数组转调 Node.js 工具；不能继续维护第二套 YAML 日期修改算法。修改用户工作区已有 `package.json` 时只合并本次需要的脚本，保留现有依赖调整。

## Risks / Trade-offs

- [Git 历史不等于真实首发历史] → 保留现有日期，补齐报告注明来源及限制，不将首次入库包装为精确恢复。
- [旧日期曾被脚本改错] → 列出日期矛盾，不自动覆盖；与本次缺失日期补齐分开处理。
- [纯路径变更、合并及删除容易漏算或误算] → 用独立临时 Git 仓库构造真实提交验证，覆盖文件重命名、目录删除和分支合并。
- [大量图片及代码文件使历史查询昂贵] → 批量索引及单次构建缓存，记录真实仓库首轮/复用缓存耗时，不引入后台服务或全量源码分析。
- [旧链接本身失效] → 逐项诊断并提示覆盖限制，既有失效引用不直接阻断全站；历史本身不可用仍必须阻止伪日期生成。
- [配套目录含构建产物] → 按明确声明追踪已版本控制文件，不擅自清理或忽略；归属预览让用户知道实际覆盖范围。
- [Vercel 历史不完整或未来构建入口漂移] → 当前 build 调用已被真实日志证实；接入历史准备和失败提示，用版本化入口及下一次构建日志验证新增逻辑。
- [当前本地包管理器与既有线上部署不同] → 核对目标版本与锁文件兼容性，不把旧锁文件生成器版本当作当前精确执行版本，也不借日期修复覆盖用户依赖调整。
- [历史重写会改变提交者时间] → 日期语义绑定当前可达历史；不承诺 rebase 或历史重写后更新时间仍相同，固定 `date` 不因此改写。
- [依赖包未来升级改变扩展行为] → 只使用仓库内适配层，并用生成 HTML 的集成验证覆盖双时间与排序。

## Migration Plan

1. 实现共享日期核心、预检与预览命令，先用临时 Git 历史测试，保留现有工作区修改。
2. 在真实仓库输出缺失日期候选、日期矛盾、资源解析问题和配套目录候选；日期写入以已确认的根仓库跟踪 source/_posts/ 文章清单为限，不将本地自动识别的工程说明纳入。
3. 写入缺失日期和已明确的配套归属；保留现有 `date` 和文件格式，不自动处理歧义归属或修正旧日期。
4. 接入 Hexo 构建与主题扩展，更新旧命令和使用说明，验证日期迁移提交不会刷新内容更新时间。
5. 完成 clean build、复用 Hexo 缓存、跨检出时间/时区及浅克隆验证；检查真实生成 HTML 和首页/归档顺序。Vercel 只核对构建入口与日志，不在本次 apply 中自动发布。
6. 回退时移除本次适配层和脚本接入、恢复本次配置修改；保留已补齐的固定 `date`。迁移报告保留变更前信息，若需撤销只恢复本次写入，不重置用户原有改动。

## Open Questions

- Vercel 实际克隆深度、远程配置及补历史能力仍需历史准备逻辑的运行结果确认；已有日志已证明调用仓库 build，因此不再把脚本是否执行当作未决问题。
- 用户本轮选择只自动追踪正文引用，不写入 mybatis 或其他未链接工程声明；updated_assets 能力保留供以后明确归属时使用。
