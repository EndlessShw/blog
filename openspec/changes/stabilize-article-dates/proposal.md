# Proposal

## Why

博客经 GitHub、Vercel 检出构建时，操作系统文件时间不代表文章历史；当前 Hexo 使用文件修改时间作为更新时间，旧 `update.py` 还会用该时间覆盖发布时间。需要将发布时间与更新时间分开，让同一 Git 版本在 Windows、Linux 和重复部署时产生一致的文章时间，真实内容修订及关联附件变化则自动反映在更新时间中。

发布时间补齐已通过提交 3167153 上线，用户已确认显示正常。49 篇缺失或空标题已通过 4193cf0 上线并由用户确认。当前实现 Git 驱动的动态更新时间，不重新改写已经确认的日期和标题。

## What Changes

- 保留已有 front matter `date`；对缺失日期的文章，提供可预览、可重复运行的迁移操作，以追溯重命名后的首次入库提交时间补齐，之后保持固定。
- 在 Hexo 构建时，从文章及其关联本地附件的有效内容变更历史派生 `updated`，不将动态更新时间反复写回源文件。
- 为 49 篇缺失或空 title 的文章补齐名称：42 篇取首个正文标题，4 篇使用用户单独确认的标题，3 篇填“标题 TODO”；其余 75 个非空 title 保留，正文与文章 URL 不改。
- 追踪正文、标题、标签和排版变更；忽略纯 CRLF/LF 转换、纯移动或重命名。按用户已确认规则，忽略仅维护顶层 `date`、`updated` 的变更，避免日期迁移刷新全部旧文章。
- 仅补齐缺失或空 title 不算内容更新；修改已有非空 title 仍算更新，不按特定迁移提交建立忽略清单。
- 自动识别正文引用的本地图片和代码附件，允许明确声明配套文件或目录；目录中受版本控制文件的增加、修改和删除均计入，未归属文件及外链变化不计入。
- 统一北京时间；首页及归档保持按发布时间排序，首页显示发布时间。沿用 Fluid 原生规则：两个时间不同时在文章开头显示更新时间，相同时只显示发布时间，不新增展示模板。
- 使旧更新入口停止用文件时间覆盖 `date`；通过仓库 `vercel.json` 明确调用统一构建入口，增加 Git 历史检查及具体问题报告，不再静默回退到文件时间。

## Capabilities

### New Capabilities

- `article-timestamps`：定义文章发布时间的持久化与补齐、基于文章和附件历史的更新时间、跨环境一致性、异常报告及页面展示。
- `article-titles`：定义缺失或空文章标题的补齐、正文标题提取、明确指定标题及“标题 TODO”占位，保持既有标题、正文与 URL。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已有能力规格。

## Impact

- 涉及 Hexo 本地脚本扩展、日期迁移命令、`package.json` 构建入口、`vercel.json`、`_config.yml`、Fluid 主题配置和仓库内展示扩展。
- 调整 `update.py` / `update.bat` 的旧日期更新行为；该入口将不再将文件修改时间当作发布时间。
- 提议在文章 front matter 使用 `updated_assets` 显式声明配套资源，不自动推断整个同级目录；既有文章及其附件归属需先预览核对。
- 构建环境需能读取本仓库所需 Git 历史。Vercel 现有部署日志已证明执行仓库 clean/build；实际克隆深度、Git 元数据及补历史能力仍需在集成时验证，历史无法获取时阻止生成伪日期。
- 优先复用现有 Node.js、Hexo、Fluid 和 pnpm；新增运行时解析依赖仅限实际需要的直接依赖，不引入外部时间数据库。
- 不批量纠正已有但可能错误的 `date`，不自动修复所有旧链接，不分析代码运行时依赖，不跟踪远程链接目标变化，不统一转换整个仓库换行符，不改变现有依赖升级或未提交的文章修改。

本提案已由用户确认进行本地实现，推送与线上发布另行安排；时间字段排除规则及旧文迁移范围已确认：仅处理根仓库跟踪的 source/_posts/ Markdown，额外工程说明和其他目录不写日期、不改渲染。
